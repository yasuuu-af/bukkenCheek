# 空室チェック手順

**判定はすべて `scripts/check_vacancy.py` が行います。AI は関与しません。**
定期実行がやることは、このコマンドを1本叩くことだけです。

```bash
export DISCORD_WEBHOOK_URL='...'      # 未設定なら
python3 scripts/check_vacancy.py --commit
```

これだけで、取得 → 判定 → 前回との差分 → Discord通知 → `state.json` / `history.md` 更新 → commit && push まで完了します。

## オプション

| コマンド | 動作 |
|---|---|
| `--dry-run` | 取得と判定だけ。送信もファイル更新もしない |
| `--commit` | 記録を更新して commit && push まで行う |
| `--fixture ミレアビターレ北千住` | 空室ありの経路を実データで確認する（動作テスト用） |

## 判定ロジック（実HTMLで検証済み）

### SUUMO

建物名キーワード検索を叩き、**物件カードが1件でも返れば掲載中**。0件なら募集なし。

```
POST https://suumo.jp/jj/common/ichiran/JJ901FC001/
     ar=030&bs=040&kwd=<建物名>
```

カード内の説明文に建物名が含まれるものだけを採用する（似た名前の別物件を拾わないため）。

> ⚠️ **`/library/` ページは判定に使えません。** 足立区の14棟を実測したところ全棟で「このページは過去の掲載情報を元に作成しています。」が出ており、募集状況を反映していませんでした。参照リンクとしてだけ残しています。

### アセットナビ

**空室があるときだけ `<div id="room_list">` と `<h2>◯◯の空室一覧</h2>` が出力される。**
満室のときは `id="agreement_yet"`（満室一覧）のみで、募集カウンタ `<li class="empty_rooms">` はHTMLコメントで潰されている。

部屋の明細は `<tr>` の属性に構造化データが入っている:

```html
<tr data-current="2" data-roomplan="1R" data-space="15.46" data-price="70000">
```

コメントを除去してから判定すること（コメント内の `room_list` を誤検出しないため）。

## 取得失敗の扱い

タイムアウト・4xx・5xx は**「空室なし」と解釈しない**。3回リトライ（2秒→4秒バックオフ）しても駄目なら、その建物を `errors` に記録し、Discord に `⚠️ 取得できなかったソース` として明示する。黙って握り潰さない。

## 通知

`notify_policy: every_run`。**空室の有無にかかわらず毎回1件投稿する。**
投稿が無い日は仕組みが止まっているサインとして扱えるようにするため。

| 状況 | status | 色 |
|---|---|---|
| 空室あり | `vacant` | 緑 |
| 変化なし | `none` | 藍 |
| 取得失敗あり | `error` | 琥珀 |

投稿には毎回、監視元4本とダッシュボードのURLが載る。空室ありの回は部屋の明細表（最大8件、超過分は件数のみ）が付く。

## ダッシュボード

`dashboard.html` は手で更新する。Artifact として再発行する場合は `docs/dashboard-url.txt` のURLを必ず `url` 引数に渡すこと（渡さないと別URLになりブックマークが切れる）。

## やらないこと

- 不動産会社への問い合わせ・申し込みなど、外部への連絡は行わない。見つけたら通知するだけ。
- Webhook URL をコミット・出力しない。このリポジトリは public。
